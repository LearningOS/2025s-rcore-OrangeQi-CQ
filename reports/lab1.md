二、深入理解 trap.S 中两个函数 __alltraps 和 __restore 的作用，并回答如下问题:

1. L40：刚进入 __restore 时，sp 代表了什么值。请指出 __restore 的两种使用情景。
    - 在进入 __restore 的瞬间，sp 指向内核栈中已分配的 TrapContext 结构的顶部。
    -  __restore 的两种情形为处理完 trap 后返回用户态、首次启动用户进程。

2. L43-L48：这几行汇编代码特殊处理了哪些寄存器？这些寄存器的的值对于进入用户态有何意义？请分别解释。
    - sstatus 寄存器：恢复用户态的中断配置（如是否允许异步中断）。
    - sepc 寄存器：存储的是用户态程序被中断时的PC值，确保从内核态返回到用户态时，程序从正确的位置继续执行。
    - sscratch 寄存器：始终持有内核栈指针，为下一次 trap 保留入口
```
ld t0, 32*8(sp)
ld t1, 33*8(sp)
ld t2, 2*8(sp)
csrw sstatus, t0
csrw sepc, t1
csrw sscratch, t2
```



3. L50-L56：为何跳过了 x2 和 x4？
    - x2 和 x4 分别是 sp 和 tp。
``` asm
ld x1, 1*8(sp)
ld x3, 3*8(sp)
.set n, 5
.rept 27
   LOAD_GP %n
   .set n, n+1
.endr
```

4. L60：该指令之后，sp 和 sscratch 中的值分别有什么意义？
    - sp 是用户栈指针，sscratch 是内核栈指针
```
csrrw sp, sscratch, sp
```


5. __restore 中发生状态切换在哪一条指令？为何该指令执行之后会进入用户态？
    - 状态切换（从内核态切换到用户态）发生在 sret 指令。
    - sstatus 是 RISC-V 的状态寄存器，其 SPP 位记录了陷阱发生前的特权级。当用户程序触发陷阱时，硬件会自动将 SPP 设为 0（表示用户态），然后切换到内核态（特权级设为 1）。执行 sret 时，处理器读取 SPP 位的值（此时为 0），将特权级恢复为用户态。
    - sepc 保存了陷阱发生时用户程序的下一条指令地址。sret 会将 PC 设置为 sepc 的值，从而继续执行用户程序。

6. L13：该指令之后，sp 和 sscratch 中的值分别有什么意义？
    - sp 是内核栈指针，sscratch 是用户栈指针
```
csrrw sp, sscratch, sp
```
7. 从 U 态进入 S 态是哪一条指令发生的？
    - 存疑：csrrw sp, sscratch, sp
